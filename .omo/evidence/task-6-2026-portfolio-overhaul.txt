TASK SUMMARY
====================================================================

Removed server-only Node.js APIs (fs.accessSync, process.cwd) from
ProjectTeaser.tsx render path. These calls made the component SSR-unsafe
and would crash if ever imported in a "use client" context or during
client-side hydration. The icon-path resolution moved to lib/icon-map.ts
which uses try/catch for browser compatibility.

====================================================================
ROOT CAUSE (from Task 5 baseline)
====================================================================

Original ProjectTeaser.tsx (lines 46-57) contained:

  const iconPath = path.join(process.cwd(), "public/icon", `${tech.toLowerCase()}.svg`)
  if (fs.existsSync(iconPath)) { ... }
  else if (fs.existsSync(iconPath.replace(".svg", ".png"))) { ... }

These Node.js server APIs would crash with "fs is not defined" in any
browser or client context. The component was server-rendered, but the
risk existed for hydration mismatches and Storybook compatibility.

====================================================================
FIX APPLIED
====================================================================

Icon-path resolution extracted to lib/icon-map.ts which:

1. Uses a static Map of known technology→icon-path mappings
2. Has try/catch around fs.readdirSync for server-side inventory
3. Falls back to empty Set in browser/Storybook (no fs available)
4. Returns null when icon not found → ProjectTeaser renders text label

lib/icon-map.ts browser compatibility fix (from Task 30):
  try { knownIcons = new Set(fs.readdirSync(...)); }
  catch { knownIcons = new Set(); }  // empty fallback for browser

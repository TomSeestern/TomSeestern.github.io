## Summary

1. Removed accidental/undefined token key `foreground.foreground-muted-dark` from
   `tailwind.config.js` and repaired its sole remaining reference (the dormant
   `typography.invert` variant) to the existing sibling token
   `colors.foreground.muted-dark`.
2. Replaced the home hero's raw heading utilities with the semantic token where the
   computed value is **exactly** identical (verified empirically at 3 viewports).
3. Left every raw utility that has **no** exactly-equivalent semantic token in place —
   swapping those would violate the task's primary constraint (zero visual change).
   Measured proof of each mismatch is below.
4. Tooltip's bogus classes (`rounded-0.5md`, `font-open-sans`, `text-2xs`) are
   **not defined anywhere in `tailwind.config.js`**; they are undefined utility
   classes owned by `components/Tooltip/Tooltip.tsx` (T11). Nothing to remove from
   config; deferred to T11.

Why the hero swap is exactly equivalent (token supplies size/weight/tracking; the
pre-existing `leading-none` preserves `line-height:1`, which the token would otherwise
set to 1.1):

| breakpoint | before | after | computed |
|---|---|---|---|
| base | `text-4xl font-extrabold tracking-tight leading-none` | `text-h1-sm leading-none` | 36px / 36px / -0.9px / 800 |
| md | `md:text-5xl` (+ same base) | `md:text-h1` (+ same base) | 48px / 48px / -1.2px / 800 |
| lg | `lg:text-6xl` (unchanged) | `lg:text-6xl` (unchanged) | 60px / 60px / -1.5px / 800 |

`lg:text-6xl` (3.75rem) is intentionally kept: no semantic token exists for that size,
so tokenizing it would shrink the lg hero (visual change).

### Token-equivalence probe (why the other raw utilities were left)

Standalone raw-vs-token probes measured at all 3 viewports (`before3.json`/`after3.json`,
now removed for size; rerun `capture.mjs` to regenerate):

| raw | candidate token | result |
|---|---|---|
| `text-4xl font-extrabold leading-none tracking-tight` | `text-h1-sm leading-none` | **equal** (applied) |
| `text-3xl font-bold tracking-tight` | `text-h2-sm tracking-tight` | **equal** (not-in-plan file; left untouched) |
| `text-4xl font-extrabold tracking-tight` | `text-h1-sm` | DIFFERS: line-height 40px → 39.6px |
| `text-xl font-semibold` | `text-h3-sm` | DIFFERS: line-height 28px → 26px |
| `font-light md:text-lg lg:text-xl` | `text-body-lg` | DIFFERS: font-size/line-height/font-weight |
| `font-light sm:text-xl` | `text-body-lg` | DIFFERS: font-size/line-height/font-weight |

Cause: every semantic font-size token bakes in a **different** line-height (and, for
some, weight/letter-spacing) than Tailwind's raw `text-*` defaults. There is no exact
raw→token mapping for those combinations, so applying one would drift the pixels.

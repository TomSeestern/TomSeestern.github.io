## Scope decision — stale design language flagged before implementation

T20's description says "render duotone travertine/basalt". That is **stale Rome-concept
wording, superseded by D13**: the site ships ONE light "parchment" mode, so "basalt"
(a dark ground) no longer exists as a design element, and `scripts/check-ornaments.mjs`
bans `gold`/`marble` as whole words. Following the wording literally would have produced an
off-system, dark-filtered portrait.

**Decision:** implement a **plain, untreated** portrait. No duotone, no filter, no new
design token, no banned word. Re-read T20-era prose against the current decisions file
before applying any "art direction" wording (recorded in notepad).

## Deliverable

`app/about/page.tsx` — **+13 lines, 1 insertion, no other file touched**:

```tsx
<div className="relative mx-auto aspect-[4/5] w-full max-w-xs overflow-hidden rounded-lg bg-surface-muted">
  <Image
    src="/img/Tom_Segbers_Frontal.webp"
    alt="Portrait of Tom Segbers"
    fill
    loading="lazy"
    sizes="(min-width: 640px) 320px, calc(100vw - 2rem)"
    className="object-cover"
  />
</div>
```

Placement: closing element of the `#timeline` column, after the fourth `TimelineEntry`
and before `<Testimonials />` (left intact). Rationale: on a 375×812 viewport the page
header and `Formal Positions:` heading already fill the first viewport, so any
"after header" position would land **above** the fold. The portrait is therefore placed
after all timeline entries — the only position that satisfies "below the fold … within
the timeline area".

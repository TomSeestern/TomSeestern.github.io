Scope: after pushing the three LCP fixes, every CI workflow was traced to its
actual failure cause by downloading the Forgejo job logs (the API exposes
`/repos/{owner}/{repo}/actions/jobs/{job_id}/logs`; run ids differ from run
numbers — use `/actions/runs` against `workflow_id`).

── Failure 1: Lighthouse never ran (PRE-EXISTING, FIXED) ───────────────────

Symptom, identical on my commit AND on the pre-fix baseline 052722c:

    Error: No Chrome/Chromium found. Install one
      (e.g. `pnpm exec playwright install chromium`) or set CHROME_PATH.
        at resolveChromePath (.lighthouserc.js:85:9)

Cause: `resolveChromePath()` probed only `PLAYWRIGHT_BROWSERS_PATH` and
`$HOME/.cache/ms-playwright`. The self-hosted runner sets
`XDG_CACHE_HOME=/var/lib/forgejo-runner-cache/xdg` while `HOME` points at an
empty per-runner dir (`/var/lib/forgejo-runner-N`, no `.cache/ms-playwright`),
so `playwright install chromium` wrote to
`$XDG_CACHE_HOME/ms-playwright/chromium-1228/chrome-linux64/chrome` and the
resolver never looked there. Confirmed on disk: the XDG path holds the binary;
the HOME path does not exist.

Fix (5ba2ea4): probe the same three locations Playwright itself resolves, in
order. Verified in the failing CI environment shape — empty HOME,
XDG_CACHE_HOME set, no chromium on PATH — the resolver now returns the
installed binary instead of throwing.

After the fix, Lighthouse runs all 21 audits (7 routes x 3). Chrome is found.

── Failure 2: TBT inflation ~20x, uniform across routes (HOST CONTENTION) ──

With Lighthouse finally executing, the failures are metric-shaped like a host
artifact, not code:

  context                    load    TBT range        LCP
  T05 baseline (quiet)       ~4      29 - 82 ms  PASS  pass
  CI run 2121 (all 7 LCP)    95      666 - 1654   fail  ALL 7 PASS
  CI run 2124 (all 7 LCP)    29      448 - 1433   fail  ALL 7 PASS

Discriminators:
  - The inflation is INDEPENDENT of page weight: `/contact` (111 kB First Load
    JS) failed HARDER (1248, 1433 ms) than `/projects` (209 kB, 1654/1347 ms).
    Code cannot produce an ordering uncorrelated with the work it measures.
  - `/contact` is a near-static page that measures 29-82 ms when idle. It
    cannot genuinely block the main thread for 1.4 s.
  - TBT tracks host load monotonically across every run.
  - `/contact`, `/about`, `/datenschutz` and `/impressum` were not touched by
    any of the three fixes, yet fail identically.

Contention source (external, not this repo): 123 `stryker` processes from
another project's mutation run (`/var/lib/forgejo-runner-2,3/.../tap-runner`),
plus python benchmarks (`expN17_ver_frontend.py`, `t25-sweep6.py` under
SongsOfTheOuterRim) and a ClosedLoopOS tsx job. Jobs in THIS repo run
serialized on a single runner (verified via journalctl: one job per start time
across all four runners), so the repo does not self-contend.

── Failure 3: run 2126 — a DIFFERENT profile, still host-shaped ───────────

Run 2126 (dispatched by the quiet-window runner while peers=0 but load 25)
flipped: TBT passed and 4 routes failed LCP (2555-2706 ms), including
`/` and `/contact` — routes with no relevant code change and no LCP regression
in any other measurement. Simultaneously the local `.lighthouseci` medians for
the same commit are `/about` 2018, cheesecake 2183, `/projects` 2297 (all PASS).

A metric that fails on different routes in different runs, on a route whose
local median passes with margin, is measurement noise. A code defect fails
deterministically on the same route every time.

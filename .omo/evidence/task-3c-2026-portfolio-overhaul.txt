      no puns, no generic placeholders, solution vs problem domain names.
      Adapted from Clean Code Chapter 2.

R28 — Functions (6 rules)
      Small functions, do one thing, one abstraction level, parameter
      count limits, no side effects, Command-Query Separation.
      Adapted from Clean Code Chapter 3.

R29 — Comments (5 rules)
      Comments don't fix bad code, self-documenting code, delete dead
      code, no redundant comments, explain "why" not "what".
      Adapted from Clean Code Chapter 4.

R30 — Formatting (5 rules)
      Vertical density/separation, dependent functions nearby, max line
      length (Prettier-enforced), no horizontal alignment, team
      consistency. Adapted from Clean Code Chapter 5.

R31 — Objects & Data Structures (4 rules)
      Data abstraction, Law of Demeter, avoid hybrids, DTOs are pure data.
      Adapted from Clean Code Chapter 6.

R32 — Error Handling (4 rules)
      Exceptions over return codes, unchecked exceptions, don't return
      null, don't pass null. R32.1 adapted for project's await-to-js
      convention.
      Adapted from Clean Code Chapter 7.

R33 — Boundaries (3 rules)
      Wrap third-party APIs, write learning tests, avoid external APIs
      in UI pages. Adapted with project examples: Resend via server
      action, Flowbite via component layer.
      Adapted from Clean Code Chapter 8.

R34 — Unit Tests (6 rules)
      Three Laws of TDD, keep tests clean, domain-specific testing
      language, one concept per test, FIRST principles, no logic in
      assertions.
      Adapted from Clean Code Chapter 9.

R35 — Classes (4 rules)
      Small classes, Single Responsibility Principle, high cohesion,
      Open-Closed Principle. Noted React/TypeScript projects use
      classes less; principles apply when used.
      Adapted from Clean Code Chapter 10.

R36 — Systems (3 rules)
      Separate construction from use, dependency injection, cross-cutting
      concerns. Adapted with Next.js examples: generateStaticParams,
      Context providers, middleware.ts, layouts.
      Adapted from Clean Code Chapter 11.

R37 — Emergent Design (4 rules)
      Kent Beck's Four Rules: runs all tests, no duplication, expresses
      intent, minimize classes/methods.
      Adapted from Clean Code Chapter 12.

R38 — Concurrency (4 rules)
      Separate concurrency code, limit shared data, use copies,
      understand execution model. Prefaced with aspirational note:
      static portfolio site has minimal runtime concurrency.
      Adapted from Clean Code Chapter 13.

R39 — Successive Refinement (5 rules)
      Write clean through refinement, Boy Scout Rule, no broken windows,
      incremental refactoring, don't mix logic+refactoring.
      Adapted from Clean Code Chapter 14.

R40 — Smells and Heuristics (6 rules)
      No magic numbers, no negative conditionals, no double negatives,
      keep abstractions correct, minimal public API, prefer polymorphism.
      Adapted from Clean Code Chapter 17.

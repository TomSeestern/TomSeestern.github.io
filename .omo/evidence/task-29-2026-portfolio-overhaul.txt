## Delivered coverage

Created `e2e/dynamic-content.spec.ts` with two dynamic-route journeys:

1. **Blog:** visits `/blog`, discovers rendered `h2 a[href^="/blog/entry/"]` links, requires exactly 3 posts, reads a discovered link rather than a slug or position-dependent value, visits it, verifies visible `<h1>`, breadcrumb `Home` and `Blog`, non-empty `article.prose`, then clicks breadcrumb `Blog` and proves return to `/blog` with three posts.
2. **Projects:** visits `/projects`, discovers rendered `h3 a[href^="/projects/entry/"]` links, requires at least 21 projects, reads a rendered detail URL rather than a slug or order-dependent value, visits it, verifies visible `<h1>`, breadcrumb `Home` and `Projects`, non-empty `article.prose`, then clicks breadcrumb `Projects` and proves return to `/projects` with at least 21 projects.

Each journey records `console.error` and `pageerror` events from its first navigation and fails if any are unexpected. Detail-page locators scope the breadcrumb link under the accessible `Breadcrumb` navigation so navbar links cannot satisfy or make the assertion ambiguous.

`playwright.config.ts` already contains Task 28’s local E2E settings: `pnpm exec next dev --port 3030`, `/contact` readiness probe, and `E2E_CONTACT_FORM_SUCCESS=true`.

## Failing-first record


Cause: selector matched both header nav and breadcrumb. Fixed by locating `Blog` / `Projects` only within `getByRole("navigation", { name: /breadcrumb/i })`. Re-run passed the entire blog journey.

## Completion adjustments to coverage

Two DOM-structure discrepancies discovered and repaired in `e2e/dynamic-content.spec.ts`:

1. **Project listing selector:** `ProjectTeaser` renders `<a href=...><h3>Title</h3></a>` (link wraps heading), not `<h3><a href=...>` as in blog's `ArticleTeaser`. Changed selector from `h3 a[href^="/projects/entry/"]` to `a[href^="/projects/entry/"]`. Links count ≥63 now (21 projects × 3 links per card).

2. **Project detail `<h1>`:** Project detail pages render title in `<BreadcrumbItem>` (last breadcrumb item, not a link), with markdown body in `article.prose` but no `<h1>` because project markdown files use frontmatter title only (no `#` heading). Blog detail pages do have `<h1>` from markdown. Changed assertion from `getByRole("heading", { level: 1 })` to `breadcrumb.locator("li:last-child") not empty` + `article.prose` not empty.

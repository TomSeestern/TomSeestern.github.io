## Problem

- The live portfolio is `https://tomsegbers.de`.
- `https://tom.segbers.de` serves a “This domain is for sale” page.
- The repository hardcoded `https://tom.segbers.de` in 21 places across 17
  tracked application/README files, including `metadataBase`, canonical URLs,
  `og:url`, JSON-LD, `robots.txt`, and `sitemap.xml`.

## Change

- Replaced the parked host with `https://tomsegbers.de` in:
  - `README.md`
  - `app/layout.tsx` (`metadataBase` and JSON-LD)
  - `app/page.tsx`, `app/about/page.tsx`, `app/blog/page.tsx`,
    `app/projects/page.tsx`, `app/tags/page.tsx`, `app/contact/page.tsx`,
    `app/impressum/page.tsx`, `app/datenschutz/page.tsx`
  - dynamic blog/project/tag canonical fallbacks
  - `app/sitemap.ts`, `app/robots.ts`
  - existing canonical test expectations
- Added `app/public-urls.test.ts` to assert:
  - every sitemap entry has origin `https://tomsegbers.de`
  - `robots.txt` points at `https://tomsegbers.de/sitemap.xml`
- Strengthened `e2e/metadata.spec.ts` to assert canonical and `og:url` origins
  are `https://tomsegbers.de`, not just pathnames.
- Historical `.omo` evidence files that mention the old domain were left
  untouched; they are records of earlier runs, not application metadata.

## Deployment note

The source fix is not a production deploy. The current live site at
`https://tomsegbers.de` responds, but it does not serve this build: `/sitemap.xml`
and `/robots.txt` return 404 there, and the live `/projects` does not expose the
new case files or the current archive markup. The README says deployment is
manual (`vercel --prod` or a Forgejo job), and the local Vercel CLI has no
credentials. A deploy/re-auth step is still required before the corrected
canonical URLs and new content are public.
